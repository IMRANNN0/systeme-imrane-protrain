# Trame adaptable de Value Map

Adapter la profondeur aux sources et à la demande ; aucun nombre de lignes, matches ou questions n'est imposé. Les inconnues restent visibles. Un inventaire préliminaire peut être livré avant un Customer Profile complet pour un produit existant.

## Périmètre et sources

Indiquer offre, segment/situation, marché/zone, date/période et objectif. Préciser point d'entrée (idée, produit existant, actualisation), version du CP et sources `S1`… avec origine, date ou date inconnue, portée et statut. Séparer mesures, déclarations, observations, interprétations et hypothèses ; signaler les contradictions. Réutiliser les données disponibles sans refaire l'intake.

## Inventaire

| Champ | Contenu |
| --- | --- |
| ID VM | VM-PS/GC/PR stable ou convention existante |
| Élément et famille | Produit/service, créateur ou soulagement ; type/angle utile |
| Capacité et mécanisme | Ce qui est livré, ce qui devrait produire l'effet et ses conditions |
| Existence | Réel documenté / déclaré non vérifié / proposé / indisponible / inconnu |
| Preuve et limites | Source/date, contrôle ou mesure réellement disponible |
| Pertinence et base | Nice-to-have → Essential, ou inconnue ; rattachement à une priorité CP sourcée |
| Faisabilité | Ressources/capacité/coûts/conditions documentés ou inconnus |

Une même capacité peut alimenter plusieurs mécanismes ; conserver le rattachement aux éléments livrés. Ne pas remplir des catégories pour compléter artificiellement le canvas.

## Matching traçable

| Champ | Contenu |
| --- | --- |
| ID CP et priorité | J/P/G, sens et priorité d'origine avec sa base ; ne pas la réinventer |
| ID VM et statut | Capacité/service ou mécanisme relieur/créateur, avec statut d'existence |
| Lien et portée | Comment cela aide ce Job, réduit ce Pain ou crée ce Gain, pour qui/quand |
| Qualité du lien | Forte / partielle / non étayée / inconnue / non ciblée, avec justification |
| Preuve et hypothèse | Ce qui est observé, ce qui reste supposé ; sources et contradictions |
| Écart | Besoin restant, condition manquante, capacité absente ou choix de non-couverture |

Présenter les priorités sélectionnées, opportunités différées et besoins non ciblés. Expliquer l'arbitrage seulement s'il est fourni/documenté ; distinguer choix, indisponibilité et inconnues de budget/capacité. Ne pas convertir le tableau en pourcentage de marché validé.

## État du fit

| Niveau examiné | À expliciter |
| --- | --- |
| Problem-Solution Fit, sens du cours | Matching conçu ; hypothèses et besoins prioritaires couverts/ouverts, sans prétendre à validation de marché |
| Product-Market Fit | Patterns de valeur délivrée et traction réellement observés, contexte d'achat, périodes/dénominateurs, limites et inconnues |
| Business Model Fit | Définitions économiques, horizon/capacité connus ou manquants ; besoin éventuel du diagnostic détaillé |

Ne pas attribuer de note ou d'étape acquise automatiquement. Si un niveau sort du périmètre demandé ou manque de données, l'indiquer sans lui inventer un verdict.

## Validation et passage

Pour les hypothèses décisives : ID → hypothèse conditionnelle → preuve confirmante/contradictoire recherchée → méthode proposée → point de décision. Questions minimales, aucune prise de contact ou exécution externe. Terminer par ce qui peut être transmis à une prochaine étape explicitement demandée (offre, FBL si sa méthode est fournie, territoires de message), avec preuves et limites ; aucune production automatique d'ads ou campagne.
