# Selective delivery checks

Choose checks that can change the result for the requested deliverable. Record the check, observed result, date, source/artifact and limitation. Explicitly mark a material unavailable check. Do not convert every example here into a mandatory task.

| Domain | Checks to consider | Evidence limits |
| --- | --- | --- |
| Website | Requested desktop/mobile flows; working navigation and CTA destination; actual form success/failure handling; truthful content; keyboard accessibility; loading behavior; requested tracking event verification | A rendered page does not prove server delivery, payment, consent or attribution. Avoid real submissions/payments without authorization. |
| Research | Primary sources when applicable; publication/observation dates; claim-to-source support; scope and counterevidence; distinction between fact, inference and unknown | A plausible citation or AI summary is not source verification. A current page does not establish historical behavior. |
| Financial model | Units/currency/time period; margin versus markup; placed/confirmed/delivered/refunded definitions; all relevant costs without double counting; zero/negative boundaries; reconciliation and sensitivity scenarios | A forecast is conditional. AOV = price × UPO assumes homogeneous pricing; use weighted order data where appropriate. Maximum affordable CPA differs from minimum required ROAS. Revenue LTV differs from contribution LTV. |
| Advertising | Real offer and destination continuity; evidence for claims; actual available guarantees and deadlines; segment/context relevance; appropriate objections; current applicable platform rules before external use | Attention, CTR or clicks do not prove demand, causation or profit. Draft copy does not authorize campaign changes, spending or publication. |
| General | Acceptance coverage; correctness on representative inputs; known failure behavior; readable handoff; material residual risks | The check must test the requested outcome, not merely match implementation wording. |

Independent review is appropriate for consequential production changes, privacy boundaries, shared governance changes or material financial decisions. It should inspect raw artifacts and evidence with its own questions. Record the reviewer's identity/role and limitations; independence is an attestation, not a property the CLI can prove.

If a relevant domain skill supplies a better test, use it. Do not rerun broad tests after successful checks unless changes or unresolved concerns justify them.
