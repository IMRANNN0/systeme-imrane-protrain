# Validation and known limits

The kit was exercised on Windows with Python 3.14.2 on 13 November 2026.
Python 3.11+ is the source requirement. macOS usage is documented; a macOS run
was not available and is not claimed.

Observed checks:

- Two full fresh installations in separate temporary paths, including spaces,
  passed no-write plans, apply, baseline hashes and structural checks.
- A third fresh installation passed after final packaging cleanup: 2,148 files,
  38 skill entrypoints, identical canonical/Claude views, one ProTrain registry
  entry, null default and destination/interpreter-specific hooks.
- The current generic engine suite ran 60 tests: 59 passed and one platform
  capability test was skipped. Routing, offline graph, runtime operations and
  managed-write protection are covered by synthetic fixtures.
- Repeating an unchanged apply succeeded. A changed working memory produced a
  preserved conflict. Existing nonempty destinations, the kit subtree and an
  original registered business lane were refused.
- Installed engine checks passed. Explicit snapshots contained all four canonical
  memories. Local graph status and synthetic lifecycle hook calls completed.
- Source engine release checks passed. These checks establish local configuration
  and execution, not native Codex/Claude hook loading or an actual worker launch.

No dependencies were installed and no network index refresh, external message or
publication was performed by the bootstrap work. Personal account, provider,
plugin and model access remain unknown on a recipient machine. Git transport is
reviewed separately by the repository owner; preserve file bytes so skill hashes
remain valid across checkout.

The installer is for a fresh destination. It preserves different files as
conflicts and does not merge, upgrade or sync a working project. Its installed
hash baseline is a comparison aid after work begins. Historical source renderers
and reference files can retain machine-specific provenance; consult the payload's
portable-workspace notes before running a component. No historical client approval
or production-readiness claim is created by installation.
